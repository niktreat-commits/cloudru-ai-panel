# Cloud.ru — подбор ИИ-сервисов на тач-панели

Посетитель выбирает отрасль, роль и задачу, меняет объём нагрузки и сразу получает рекомендацию и предварительный расчёт. Контакты можно оставить, чтобы получить документ после конференции. Приложение само не отправляет письма: документы сохраняются для последующей работы команды.

Эта версия включает сервер Node.js и приватное Object Storage. Старый контейнер с nginx необходимо пересобрать по новому Dockerfile. Порт остаётся **8080**.

## Что изменилось

- Палитра из брендбука: графит `#222222`, зелёный `#26D07C`, белый и нейтральный серый. Заголовки SB Sans Display, текст Verdana как допустимая замена отсутствующего SB Sans Text. Шрифты и логотип загружаются локально.
- Бюджет и ограничения видны сразу. Детали модели и запуска раскрываются отдельно, размещение остаётся на основном экране.
- Для помощника разработчика отдельно считаются чат о коде и автодополнение. Вводятся размер команды, доля активных пользователей и частота, включая значения выше 60. Настройки по умолчанию — примеры, не нормы рынка и не тариф GigaCode.
- Нагрузка не переключает способ запуска. GPU подбираются по пику в активные часы; срок аренды задаётся отдельно. Автомасштабирование не выдаётся за измеренный прогноз.
- Выборы сохраняются в фоне без контактов и свободного текста. Через 35 секунд бездействия появляется предупреждение, через 45 — сохранение завершения и полный сброс.
- Имя и фамилия, компания, должность, почта и телефон обязательны в форме. Отдельное согласие не отмечено заранее. Введённые контакты не сохраняются до отправки формы.
- Успех показывается после записи лида и задания на DOCX в S3. Через пять секунд экран благодарности сбрасывается; контакты удаляются из состояния интерфейса сразу после подтверждения.

## Развёртывание

Подробные действия: [DEPLOY-WORKFLOW-STUDIO.md](DEPLOY-WORKFLOW-STUDIO.md). Для запуска нужен Node.js 22+; Dockerfile использует Node.js 24.

```bash
npm ci
npm test
cp .env.example .env
```

Заполните `.env` локально и запускайте:

```bash
node --env-file=.env server/index.mjs
```

Файл `.env` не загружается в GitHub. В Container Apps значения задаются через переменные и секреты сервиса, а не через файлы репозитория.

| Переменная | Значение |
| --- | --- |
| `S3_BUCKET` | `cloudru-aij-leads` |
| `S3_ENDPOINT` | `https://s3.cloud.ru` |
| `AWS_REGION` | `ru-central-1` |
| `AWS_ACCESS_KEY_ID` | `<tenant_id>:<key_id>` |
| `AWS_SECRET_ACCESS_KEY` | Key Secret сервисного аккаунта |
| `SESSION_SECRET` | Случайный постоянный секрет длиной не менее 32 символов |
| `PUBLIC_ORIGIN` | Полный HTTPS-адрес приложения, без завершающего `/` |
| `EVENT_ID` | `aij-2026` |
| `KIOSK_ID` | Например `stand-1` |
| `LEGAL_APPROVED` | `true` после согласования текста и условий обработки внутри компании |

`AWS_ACCESS_KEY_ID` содержит Tenant ID, потому что так Cloud.ru определяет пространство аутентификации ключа. Имя бакета передаётся отдельно. В AWS SDK включён `forcePathStyle`: запросы идут на `https://s3.cloud.ru/cloudru-aij-leads/...`. Не добавляйте имя бакета в endpoint.

Альтернатива составному `AWS_ACCESS_KEY_ID` — отдельно задать `S3_TENANT_ID` и `S3_KEY_ID`; если задан `AWS_ACCESS_KEY_ID`, он имеет приоритет.

Сгенерировать `SESSION_SECRET` на своём компьютере:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Секрет одинаковый для всех реплик приложения. Он подписывает доступ посетителя только к его собственной сессии. Ключи S3 в браузер не передаются.

## Что находится в бакете

```text
sessions/2026-10-23/<session-id>/00000001.json
sessions/2026-10-23/<session-id>/00000002.json
leads/2026-10-23/<session-id>/lead.json
leads/2026-10-23/<session-id>/card.docx
jobs/documents/<session-id>.json
```

**sessions** — история подбора: случайный ID, время, отрасль, роль, выбранная задача, просмотренные задачи, параметры расчёта, размещение, сервисы, оценка бюджета, версия методики и тарифов, максимальный достигнутый шаг и причина завершения. Нет имени, компании, должности из формы, почты, телефона, IP, User-Agent и свободного описания задачи. После появления лида сессия связана с человеком и требует соответствующей защиты.

Снимки имеют номера. Для итогового состояния берётся наибольший `revision`, поэтому поздняя доставка старого запроса не затирает завершение. В норме сохраняется несколько снимков за подбор, а не запись на каждый жест. Выборы при коротком сетевом сбое повторяются в фоне; при длительном отсутствии сети, закрытии вкладки или аварии несохранённая часть может потеряться. Сервер не заявляет об успехе до записи в S3.

**leads** — контакты, финальная спецификация, просмотренные задачи, расчёт, точный текст согласия, его версия и SHA-256, серверное время получения. DOCX создаётся в фоне. В пределах одной сессии создаётся одна карточка; повторная отправка с тем же ключом не создаёт новый лид.

**jobs/documents** — служебные задания без контактов. Они хранятся в S3 и восстанавливаются после перезапуска. Задание удаляется после успешной записи DOCX. Для постоянной обработки держите минимум одну запущенную реплику. Если приложение остановлено, карточка появится после его следующего запуска или ручного запуска обработчика.

## Персональные данные

`config/legal.json` содержит **проект** отдельного согласия для подготовки подборки и связи по выбранной задаче. Данные оператора и ссылка взяты из опубликованной политики Cloud.ru; назначение обработки, срок 90 дней и маршрут отзыва требуют внутреннего согласования. Согласие не включает рекламу. Полный текст сохраняется в JSON заявки, краткие реквизиты — в DOCX.

Перед включением формы ответственному за ПДн нужно подтвердить оператора, цель, перечень данных, срок, порядок отзыва, актуальность политики и применимость уведомления Роскомнадзора/защитных мер к этому процессу. Размещение приложения и бакета должно обеспечивать требуемую локализацию в РФ. Сам по себе приватный S3 не обеспечивает все требования законодательства.

После согласования отредактируйте текст, задайте новую `version`, пересоберите образ и установите `LEGAL_APPROVED=true`. До этого калькулятор и сессии работают, форма не принимает контакты. Это настройка запуска, а не автоматическая юридическая проверка.

Настройте правила жизненного цикла бакета: `sessions/` — 30 дней, `leads/` и `jobs/` — 90 дней либо ваши согласованные сроки. Если меняете сроки, синхронно измените `retentionDays` и текст в `config/legal.json`, а для сессий — `sessionsRetentionDays` в `server/config.mjs`. `expiresAt` — метка для обработки, она сама не удаляет объекты. Жизненный цикл обычно удаляет объекты с задержкой; для отзыва/достижения цели удаляйте карточку, связанные снимки, задания и выгрузки по процедуре компании в установленный срок. При включённом версионировании учитывайте старые версии и маркеры удаления.

Доступ к бакету — только уполномоченным сотрудникам и сервисному аккаунту. Публичное чтение, CORS для браузера и публичные ссылки не нужны. Если нужны резервные копии, их доступ и сроки также входят в правила обработки. Не отправляйте выгрузки с контактами в GitHub.

## Проверки и выгрузка

Проверить реальный S3 без контактных данных (создаёт и удаляет один тестовый объект в `checks/`):

```bash
node --env-file=.env scripts/check-storage.mjs
```

Повторно обработать ожидающие документы:

```bash
node --env-file=.env scripts/retry-documents.mjs
```

Выгрузить итоговые состояния сессий и карточки для работы команды:

```bash
node --env-file=.env scripts/export-sessions.mjs data/sessions.json
node --env-file=.env scripts/export-leads.mjs data/leads
```

Каталог `data` исключён из Git. Нужны права на `PutObject`, `GetObject`, `ListObjectsV2`, `DeleteObject`, `HeadBucket` в выбранном бакете. Роли `s3e.viewer` и `s3e.editor` на самом бакете покрывают эти операции; администраторский доступ на весь тенант не требуется.

`/healthz` проверяет процесс. `/readyz` проверяет доступность бакета; не используйте зависимость от S3 как liveness-проверку, иначе краткий сбой хранилища будет перезапускать исправный калькулятор. В ответах API и логах нет контактов. Для стенда проверяйте индикатор сохранения и состояние обработчика документов; мониторинг ошибок HTTP и S3 настраивается средствами вашей инфраструктуры.

## Расчёт и границы оценки

Основные файлы — `dist/scenario-calculator.mjs`, `dist/pricing.json`, `dist/specification.mjs`. Сервер повторно рассчитывает спецификацию: бюджет из браузера не считается достоверным. При изменении методики повышайте `METHOD_VERSION` и обновляйте тарифную дату/источники.

В API считаются входные и выходные токены. Размер контекста, ответы, число действий и пики — явные допущения. В GPU-режиме используется условная производительность из тарифного снимка, а не измеренная скорость пользовательской модели. Для CV и обучения без замера показывается следующий шаг вместо выдуманной цены. Частное и гибридное размещение требуют отдельного подбора; доступность облачного сервиса в частном контуре не обещается. Хранение, RAG, OCR, агенты, интеграции и эксплуатация не подменяются ценой токенов.

## Локальная проверка интерфейса

```bash
npm run dev
```

Это отдельный режим QA с временным хранилищем в памяти и тестовой конфигурацией согласия. Для локального просмотра откройте `http://localhost:4173`; для локального Origin задайте `PUBLIC_ORIGIN=http://localhost:4173` перед запуском. Тестовые данные теряются при остановке процесса. В рабочей среде используйте Dockerfile или `npm start`, которые всегда подключают настоящий S3.

Автоматические тесты проверяют расчёты, отсутствие падения цены при росте нагрузки, согласие и телефон, исключение контактов из сессий, собственность сессии, сетевые повторы, восстановление задания на DOCX и границы HTTP API. Реальное подключение к вашему бакету нужно проверить командой выше после задания ключей.

Официальная схема аутентификации: https://cloud.ru/docs/s3e/ug/topics/api__api-key
